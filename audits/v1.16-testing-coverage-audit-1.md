## 1. Executive Summary

Portier's testing and coverage strategy is **meaningful, layered, deterministic, and intact** after the v1.14 NestJS and v1.15 chi-router migrations. The full validation matrix is green:

- `npm run test` (shared + server + client + Go service) — ✅ all pass.
- `npm run test:cli` — ✅ all 10 CLI packages pass.
- `npm run validate:contract` — ✅ **234 passed, 0 skipped, 0 failed** (boots TS + Go).
- `npm run validate:openapi:go` — ✅ green.
- `npm run validate:coverage:service` — ✅ **90.3% statements / 96.6% functions** (gate 90/95).
- `npm run validate:coverage:replay` — ✅ **96.5% statements / 98.9% functions** (gate 95/95).
- `npm run lint` — ✅ clean; `npm run typecheck` — ✅ clean.

Coverage layers are well-structured and non-overlapping: contract (TS↔Go behaviour parity) vs OpenAPI inventory (static route/status drift) vs per-runtime unit/integration vs CLI/replay module gates vs runtime smoke. Determinism discipline is in place (Test-A free-port/bind-retry helpers, child-process cleanup guard, deterministic offline artifacts). Gates are not lowered, structural exceptions are documented, and there is **no coverage theater** (no fake entry/platform/logger tests).

**No blocking findings.** The carried **lint-policy item (L-1)** is confirmed real but **low-risk to adopt**: the repo already uses a flat `typescript-eslint` config, and **production code has zero `any` usages today** (the 11 `any` uses are all in tests), so a production `no-explicit-any` guardrail would be essentially free — but React Hooks rules are not active (plugin not installed), strict/stylistic type-checked rules are not applied, and there is no `--max-warnings 0`. Recommended as a **dedicated lint-hardening slice** (natural fit for v1.19 RC hardening), not done here. Three other non-blocking notes carry prior-audit test follow-ups (R-1 autostart-recovery test, O-1 UDP-prune reclaim test, Go config/forwarders/activity error-path coverage). No remediation performed.

**UI flows covered; lint posture is the carried L-1 item.**

**Testing:**

Deliberately not in `npm run test`.
- **Contract-drift safety:** E2E exercises real runtime; unit tests use `page.route`/fixtures only to force otherwise-undeterministic failure states — they do not over-mock the API in a way that hides contract drift (the contract is independently guarded by `validate:contract`).
- **Function gate (78):** notably lower than statements — reflects UI helper/handler functions + Windows vitest ghost-entry variance (documented ±1%). Not raised (thin/variance).

**Lint policy (L-1 — carried item):** the current `eslint.config.js` is a flat `typescript-eslint` config with `js.configs.recommended` + `tseslint.configs.recommended` (NON-type-checked) + `projectService` on, `@typescript-eslint/no-explicit-any: "off"` (globally), and `no-unused-vars` with `^_` ignore. Measured against the desired policy:

| Desired | Current | Risk to adopt |
|---|---|---|
| Flat config + `typescript-eslint` | ✅ present | — |
| **strict** type-checked rules | ❌ only `recommended` | MEDIUM–HIGH (no-unsafe-*/no-floating-promises noise — needs an evaluation pass) |
| **stylistic** type-checked rules | ❌ absent | MEDIUM |
| React Hooks recommended (client TSX) | ❌ `eslint-plugin-react-hooks` **not installed** | LOW–MEDIUM (add plugin; evaluate existing TSX) |
| production `no-explicit-any` forbidden | ❌ off globally — **but production has 0 `any` today** | **LOW (essentially free)** |
| tests may allow `any` | ❌ no split (off globally) | LOW (add a test-files override) |
| `--max-warnings 0` | ❌ plain `eslint .` | LOW once rules are clean |
| React Refresh rule (intentional) | ❌ `eslint-plugin-react-refresh` not installed | optional/intentional |

**Adoption finding:** the `no-explicit-any` (production-forbid + test-allow) portion is **zero-risk today** (grep: **0** `any` in production TS; 11 in tests) — it is a future-proofing guardrail, not a cleanup burden. React Hooks + strict/stylistic type-checked rules carry real noise risk and need an evaluation pass. **Recommendation:** a **dedicated lint-hardening slice** (good fit for v1.19 RC hardening) that (1) adds the production-`any`-forbid + test override (cheap), (2) adds `eslint-plugin-react-hooks` recommended for client TSX, (3) evaluates `strictTypeChecked`/`stylisticTypeChecked` and fixes/justifies the resulting set, (4) flips `--max-warnings 0`. **Not implemented here** — the full policy is not "very small," and partial cherry-picking would be an odd half-measure mid-audit.
