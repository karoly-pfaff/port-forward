# v1.16 Observability & Replay Audit (1)

**Audit:** v1.16 Audit Set #5 — Observability and Replay
**Date:** 2026-06-17
**Baseline:** v1.15.0 shipped (NestJS single TypeScript runtime; Go preferred packaged runtime; chi router; `app.App` container).
**Previous audits:** #1 Contract Parity — PASS; #2 Architecture & Module Boundary — PASS; #3 Resilience & Data Durability — PASS WITH NOTES; #4 Security & Local-Safety — PASS WITH NOTES.
**Type:** Read-only audit + zero behaviour change. No telemetry, no external calls, no API/contract/router change.
**Verdict:** ⚠️ **PASS WITH NOTES** (no blockers; one real non-blocking leak in the UDP session registry).

---

## 1. Executive Summary

Portier's observability surfaces — the activity stream, status/runtime/connection/session reporting, diagnostics/support-bundle outputs, CLI run history, and the offline replay tool — are **useful, local-safe, and (for the offline artifacts) deterministic**. The v1.14/v1.15 migrations introduced no observability regression, and there is **no telemetry or external network call anywhere**.

- **Activity stream:** 17 event types + 4 severities, identical in Go and TS (parity-tested by `validate:contract`); bounded (500), thread-safe, newest-first, **ephemeral by design**; events emitted *after* the relevant state transition; payloads carry topology only (no secrets); `Clear` affects activity only; filters apply before the limit. Diagnose intentionally emits **no** activity (it is read-only) — a deliberate consistency choice, not a gap.
- **Status/runtime/connections/sessions:** status reflects runtime truth after start/stop/error (no false running state — confirmed audit #3); TCP connections are tracked and **removed on socket close**; runtime metadata is useful; Go-only `/api/health` and Nest-only `/health` remain documented exceptions; `/api/runtime` local-path exposure is intentional local diagnostics (audit #4).
- **Diagnostics/support-bundle:** deterministic (ordered doctor checks); excludes env vars, process lists, logs, tokens, secrets, and filesystem scans; `manifest.json` is written **last** as a completeness marker and lists its artifacts/source; AI-handoff prompts caution review-before-sharing.
- **CLI run history:** opt-in (`--record-history`), bounded (100 runs), **versioned** (`schemaVersion: 1`), compact metadata only — no raw configs/policies/reports/logs/env/runtime-URLs/tokens/secrets; write-failure surfaces as a warning that never hides the run result.
- **Replay:** a standalone module, **fully offline and read-only** (no `net/http`/`os/exec`/`os.Getenv`; reads only the supplied artifact and, for a bundle directory, ONLY that bundle's own `manifest.json`/`report.json`/`explanations.json` — never the referenced config/policy files); detects artifact kind by shape/`schemaVersion`; fails cleanly (exit 2) on malformed/unsupported input; deterministic output (sorted distributions); coverage 96.5%/98.9%.

**No blocking findings.** Three **non-blocking** notes: (O-1) **`PruneExpired`/`pruneExpired` is defined but never wired to a periodic sweep in either runtime**, so one-way UDP session-registry entries accumulate per distinct client until rule stop (the *snapshot filters* expired entries from the reported view, so observability stays correct, but the underlying map grows) → follow-up fix slice; (O-2) the live `/api/connections` TCP/UDP **detail arrays are map-iteration order** (non-deterministic) — cosmetic for a live view; (O-3) docs do not record the prune limitation or the diagnose-emits-no-activity intent (docs-only). No remediation performed (O-1's fix is a behaviour change reserved for a dedicated slice).

## 5. Status / Runtime / Connections / Session Reporting Findings

**Reflects runtime truth, with one registry-growth leak.**

| Surface | Finding |
|---|---|
| `/api/status` | Reflects runtime truth; **no false running state** after a failed start (Go sets `lastError`, no running; TS `getStatus` derives running from `forwarders.has` — audit #3). Health derived deterministically by the manager. |
| `/api/runtime` | Useful metadata (version/runtime/uptime/pid/host/port/paths/serviceMode); `configPath`/`staticDir` path exposure is intentional local diagnostics (audit #4 S-2). Not misleading after restart (uptime/startedAt reflect the new process). |
| `/api/connections` | `RuleSummaries` aggregated per rule **in rule order** (deterministic). Volatile `generatedAt` from the shared clock (audit #1). |
| `/api/health` (Go) / `/health` (Nest) | Documented liveness exceptions (audit #1). |
| TCP live tracking | Connections opened/tracked, byte counters via `countingWriter`, **removed on socket close** (`handleClient` defer → `CloseConnection`) and on rule stop (`CloseConnectionsForRule`). **No TCP leak.** |
| UDP live tracking | bidi-multi sessions: per-session 60 s idle timer → `expireSession` → `CloseSession` (cleaned). bidi-last: at most ~1 session (prev closed on client change). **one-way: see O-1.** |
| Counters | TCP/UDP counters are atomics; coherent for diagnostics. Snapshot computes `durationMs`/`idleMs`/`status` (active/idle) relative to `now`. |
| Stale entries in the view | Snapshots **filter out expired** (>5 min idle) sessions, so the *reported* live view never shows stale entries even when the map still holds them. |

> ### Finding O-1 (non-blocking): un-wired `PruneExpired` → one-way UDP session-registry growth
>
> Both runtimes define a registry prune (`UdpSessionRegistry.PruneExpired` / `UdpSessionRegistry.pruneExpired`) intended to drop sessions idle beyond the 5-minute expiry, **but neither is called anywhere in production** (no ticker/`setInterval`; grep finds only the definition). Removal of UDP session entries therefore relies on:
> - the forwarder's per-session idle timer (**bidi-multi only** — `expireSession` → `CloseSession`),
> - prev-session close on client change (**bidi-last** — bounded to ~1),
> - `CloseSessionsForRule` on rule/forwarder stop.
>
> For **one-way mode** the forwarder calls `OpenOrTouchSession` per inbound packet (keyed by `ruleID:mode:client:port`) but **never closes those sessions** except on rule stop. With `PruneExpired` un-wired, a long-lived one-way UDP forward that receives packets from many distinct client endpoints **accumulates registry entries unbounded** (bounded only by distinct-client cardinality and rule lifetime). The `Snapshot` filters expired entries from the **reported view** (so `/api/connections` stays correct), but the underlying `entries`/`keyToID` maps grow — a slow memory leak. The TCP registry is unaffected (entries removed on socket close).
>
> **Impact:** non-blocking for typical forwards (few/fixed clients; rule stop clears the map), but a genuine resource leak for a high-cardinality one-way UDP forward on a long-running rule. Present in **both** runtimes (parity), so it is pre-existing, not a migration regression.
>
> **Recommended direction (a dedicated fix slice, not this audit):** wire `PruneExpired` to a periodic sweep (or prune within `Snapshot`/on-write, or hard-cap the registry) in both runtimes, with a test that proves one-way entries are reclaimed. Candidate for v1.17 (resilience) or v1.19 (RC hardening). Wiring it is a behaviour change, so it is **not** done here.

> ### Finding O-2 (minor, non-blocking): non-deterministic live detail-array ordering
>
> The TCP/UDP registry `Snapshot` methods iterate a Go `map` and append without sorting, so the `tcpConnections`/`udpSessions` **detail arrays** in `/api/connections` are in non-deterministic order (the per-rule `ruleSummaries` are rule-ordered and deterministic). This is **cosmetic for a live view** — all entries are present and counts are correct. If stable ordering is ever wanted (stable UI rendering, snapshot diffing), sort the snapshot by `startedAt`/`id`. No action for v1.x.

## 6. Diagnostics / Support-Bundle Findings

**Deterministic, local-safe, completeness-marked. PASS.**

- **Diagnose** (`POST /api/forwards/:id/diagnose`): ordered checks (listen-host → LAN-exposure → privileged-port → common-port → listen-bind → target-host → target-connect → udp-mode) + summary; deterministic ordering (parity-tested per the v1.7 Slice 5 ordering tests); read-only; no raw socket-error dumps (returns check status + message).
- **CLI support-bundle** (`supportbundle.go`): writes `manifest.json` (schema version, time, CLI version, artifacts, warnings), `doctor.json`/`doctor.txt`, `explanations.json`, and (when reachable) `runtime.json`/`config-export.json`. **Manifest is written LAST** ("its presence marks a complete bundle") — a clear completeness indicator. **Source attribution:** the manifest records `source`/`generatedBy`/`runtimeUrl` and lists the artifacts; each artifact is a named, self-describing JSON file. **Safety:** deliberately excludes OS env vars, process lists, logs, tokens, secrets, and arbitrary filesystem scans (documented in the help, the manifest comment, and the CLAUDE.md durable rule). MAY include rule names/hosts/ports + the runtime's `configPath`/`staticDir` — intentional diagnostics (audit #4 S-2/S-3).
- **CLI diagnostics-export** (`diagnostics.go`): "does not include logs, environment variables, OS usernames, or raw files from disk."
- **AI-handoff prompts** (`prompts/{doctor,policy,workflow}.md`): caution "review the content before sharing it with a third-party service," state the pasted content is the only source of truth, and tell the assistant not to invent state — so diagnostics do not claim more authority than they have.

Findings: none blocking. (Topology/path sensitivity = audit #4 S-2/S-3.)

## 7. CLI History Findings

**Opt-in, bounded, versioned, compact. PASS.**

- **Opt-in:** recorded only with `workflow run --record-history`; no always-on collection.
- **Bounded:** `historyMaxRuns = 100` (newest kept, oldest dropped); `PruneHistory` keeps newest N.
- **Versioned:** `HistorySchemaVersion = 1` stamped on the document (`History.SchemaVersion`) — supports future migration.
- **Compact metadata only:** `HistoryRun` = id/createdAt/workflow/result/summary/`[]HistoryStep`; `HistoryStep` = compact metadata (id/type/status/exitCode). The v1.12 durable rule excludes raw configs, raw policies, full reports, file contents, logs, env vars, process data, secrets, runtime URLs, and auth tokens (confirmed audit #3/#4).
- **Storage/local:** `<user-config-dir>/portier/workflow-history.json`; fully local; `list`/`stats`/`export`/`prune`/`clear` are offline.
- **Write-failure behaviour:** a history write failure is a warning that never hides the run result (audit #3) — and is exercised by tests.
- **Useful for troubleshooting:** stats/filter/export support local trend inspection without exposing sensitive data.

Findings: none.

## 8. Replay Correctness / Safety Findings

**Offline, deterministic, validating. PASS.**

- **Offline & read-only:** the replay module imports no `net/http`, `os/exec`, or `os.Getenv` (grep clean); it never contacts the runtime, executes commands, or uploads. Its only file reads are `os.ReadFile` on the **supplied** `--from`/`--left`/`--right` artifact and, for a support-bundle **directory**, ONLY that bundle's own `manifest.json`/`report.json`/`explanations.json` — it never opens the config/policy/baseline files an artifact *references* (confirmed across `detect.go`/`analyze.go`/`compare.go`/`explain.go`/`timeline.go`). Standalone module (`portier/replay`), `core` is a leaf (audit #2).
- **Versioned-artifact aware:** `detect.go` classifies artifacts by JSON/manifest shape + `schemaVersion`; local replay schemas carry `schemaVersion: 1`.
- **Fails cleanly:** unreadable/malformed/unsupported input → exit 2; output-write/encode failure → exit 1; no exit 3 (never contacts a runtime). Does not silently ignore malformed sections (a malformed report in a bundle is tolerated with a minimal analysis — documented behaviour, not a silent drop).
- **Deterministic:** distributions sorted (count desc, then key asc); IDs/lists sorted; arrays serialize as `[]` not `null`; `--json` stdout and `--out` are byte-identical (single marshaller) — per the v1.13 durable rules.
- **Source attribution:** each output records `source` (the detected artifact kind, e.g. `workflow-run-report`/`replay-compare`) so offline troubleshooting cites its origin.
- **Backward compatibility:** detection is shape/version-based; unknown codes are preserved (`explain` marks them `known:false`); mixed-kind compares are explicitly marked limited rather than failing.
- **Tests:** `validate:coverage:replay` PASS at **96.5% statements / 98.9% functions** (gate 95/95) — the suite covers valid, invalid, edge, no-input-mutation, and does-not-read-referenced-files cases (v1.13 Slices 1–7).

Findings: none. (Replay does not rely on current runtime internals — it defines its own minimal local DTOs, audit #2.)

## 14. Verdict

**Blocking notes:** none.

1. **O-1** — `PruneExpired`/`pruneExpired` is unwired; one-way UDP session-registry entries grow unbounded until rule stop (the reported view stays correct; the map leaks). Both runtimes. → **dedicated fix slice** (v1.17 resilience or v1.19 hardening) + a reclaim test.
2. **O-2** — live `/api/connections` detail arrays are non-deterministically ordered (cosmetic; summaries are deterministic).
3. **O-3** — docs don't note the prune limitation or the diagnose-emits-no-activity intent (best landed with the O-1 fix).
