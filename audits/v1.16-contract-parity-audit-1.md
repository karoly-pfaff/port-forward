# v1.16 Contract & Runtime Parity Audit (1)

**Audit:** v1.16 Audit Set #1 — Contract and Runtime Parity (run first, per the v1.16 plan)
**Date:** 2026-06-17
**Baseline:** v1.15.0 shipped (NestJS single TypeScript runtime; Go preferred packaged runtime; chi owns all Go API routes; `app.App` dependency container; no Go legacy dispatch)
**Type:** Read-only audit + zero behaviour change. No production code, schema, router, or contract was modified.
**Verdict:** ✅ **PASS**

---

## 1. Executive Summary

After the v1.14 NestJS migration and the v1.15 Go chi-router migration, the canonical API contract, both runtimes, the OpenAPI artifacts, the contract validator, the Go route inventory, runtime metadata, and the durable docs are **aligned with no contract drift**.

- Canonical contract ownership is correct and consistently documented: the **NestJS-generated `server/build/api/openapi.json`** is the single source of truth; `docs/api/openapi.json` is a tracked synced copy; the Go inventory gate validates against the canonical primary; `validate:contract` is the TS↔Go behaviour-parity guard.
- `npm run generate:apidoc` is deterministic (regeneration produced **no git diff**).
- `npm run validate:openapi:go` is **green** — the Go route/method/status inventory matches the canonical OpenAPI both directions, with the two intentional whitelists intact.
- `npm run validate:contract` is **234/234, 0 skipped, 0 failed**, exercising both the TypeScript (NestJS) runtime and the Go runtime (cross-runtime content parity + CLI DTO parity guard all green).
- All version surfaces report **1.15.0**; the OpenAPI doc `info.version` is **1.15** (project minor-version convention) and the runtime `version` example is **1.15.0** — consistent.
- No stale "Express" / "legacy dispatch" **contract-ownership** wording remains in current-guidance docs (the only "Express" hits are period-accurate historical slice logs in `docs/checklist.md`, which are preserved by policy).

**No blocking findings.** Two **non-blocking follow-ups** are recorded (hardcoded version-example maintenance points; generic-500 not modelled — already documented policy). Neither warrants a fix inside this audit slice.

## 6. Response Status Parity Findings

**Confirmed aligned.** `route_inventory_test.go` `statusDiffs` runs **both directions** (every OpenAPI status present in Go; every Go status present in OpenAPI) and `validate:openapi:go` is green, so the documented contract statuses match for all canonical paths.

| `POST /api/ports/advisory`→`GET` | 200, 400 | ✅ |

- **Generic/unexpected 500 (no-leak):** intentionally **not enumerated** in the inventory or OpenAPI for any operation (the `writeManagerError` universal path). The `route_inventory_test.go` header documents this as policy. ✅ consistent with the stated approach — **not normalized**.
- **404-not-405:** a wrong method on a known path and an unknown `/api/*` path both return the generic `/api` JSON 404 envelope via `writeAPINotFound` (chi `NotFound`/`MethodNotAllowed`), never a 405. Documented in `service/readme.md`. ✅ left intentional, not made "more RESTful".
- **Go-only `GET /api/health`** and **OpenAPI-only `GET /health`** behave exactly as the whitelists describe. ✅

No undocumented status drift found.

## 7. Request / Response Shape Parity Findings

Comprehensive byte-for-byte shape parity is owned by `validate:contract` (234/234 against both runtimes) plus the **CLI DTO parity guard** (`TestCLIDTOContractParity`, which strictly decodes live runtime JSON into the CLI DTOs). This audit additionally spot-checked the highest-traffic shapes against the Go domain types:

| Shape | OpenAPI | Go | Result |
|---|---|---|---|
| Error envelope `ApiErrorResponseDto` | `{ errors: string[] }`, `errors` required | `writeAPINotFound`/`writeManagerError` emit `{"errors":[...]}` | ✅ match |
| `ForwardStatusDto` | props `ruleId, running, health, bytesIn, bytesOut, packetsIn, packetsOut, activeConnections, activeUdpSessions, lastError, startedAt`; required `ruleId, running, health, bytesIn, bytesOut` | `domain.ForwardStatus` with matching json tags (`activeConnections`/`lastError`/`startedAt` `omitempty`) | ✅ match |
| `health` enum | `healthy` \| `warning` \| `error` | `domain.RuleHealth` consts `HealthHealthy/Warning/Error` | ✅ match |
| `RuntimeInfoResponseDto` | 13 required props incl. `runtime` enum `node`\|`go`, `platform`/`arch` enums | `/api/runtime` Go handler + shared `buildRuntimeInfo` | ✅ match (verified via `validate:contract` + status gate) |

Focused review of the remaining families (forward rule response, live connections, activity, config export/import/plan/apply, 204 no-body) found:

- No schema field documented but absent in Go, and no Go field undocumented in OpenAPI (would fail `validate:openapi:go` status/shape membership and `validate:contract`).
- No nullable/optional, enum, array-vs-envelope, or version-example drift.
- Error envelope shape is uniform across both runtimes.

**Classification:** no shape mismatch found — nothing to fix.

## 8. Contract Validation Coverage Findings

`scripts/validate-contract.js` is a **behaviour-parity** validator (distinct from `validate:openapi:go`, which is a static route/status drift gate). It runs an ordered registry of **15 scenario-group functions**:

`runRuntimeScenarios`, `runForwardsScenarios`, `runRuleGroupScenarios`, `runGroupActionScenarios`, `runRuleHealthScenarios`, `runForwardLifecycleScenarios`, `runActivityScenarios`, `runConfigExportImportScenarios`, `runPortAdvisoryScenarios`, `runForwardDeleteScenarios`, `runConnectionsScenarios`, `runConfigPlanScenarios`, `runConfigApplyScenarios`, `runErrorEnvelopeScenarios`, `runDiagnoseScenarios`.

Plus: activity value-set source-of-truth parity (TS union ↔ Go consts ↔ canonical 17 types / 4 severities), cross-runtime **content** parity (`compareParity` — advisory/group/plan/health payloads diffed field-by-field), and the **CLI DTO parity guard** (Arch-D).

| Question | Answer |
|---|---|
| Each OpenAPI operation has ≥1 contract scenario? | ✅ Every endpoint family is covered by a scenario group (forwards CRUD/lifecycle/reorder, groups, status, runtime, activity, connections, config export/import/plan/apply, ports advisory, diagnose). |
| Negative/error paths represented? | ✅ `runErrorEnvelopeScenarios` + per-group rejection cases (400/404/409/422). |
| Config special cases represented? | ✅ plan/apply/import groups incl. duplicate-binding, drift, dry-run, destructive-gating, `422 {errors, result}`. |
| Wrong-method / unknown-route semantics covered? | ✅ Covered by `validate:openapi:go` + the Go `router_contract_test.go` (404-not-405, static-vs-API boundary) — appropriately **not** duplicated in the cross-runtime validator. |
| Overlap with `validate:openapi:go` clear? | ✅ Distinct: `validate:contract` = live TS↔Go behaviour parity; `validate:openapi:go` = static Go-inventory-vs-OpenAPI drift. Documented in `service/readme.md` and the durable rules. |

**Result:** `npm run validate:contract` → **234 passed, 0 skipped, 0 failed** (both runtimes exercised; Go binary present and parity-checked).

**Gaps:** none blocking. (Follow-up idea for a later v1.16 audit, non-blocking: the generic-500 no-leak path is intentionally unmodelled and so not contract-asserted — covered instead by Go unit tests; this is existing documented policy, not a parity gap.)
