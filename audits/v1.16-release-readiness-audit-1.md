## 1. Executive Summary

Portier's release-readiness machinery — version surfaces, changelog/checklist flow, OpenAPI artifact flow, package/runtime layout + smoke, the release-validation matrix, and platform scripts — is **coherent and consistent** after the v1.14/v1.15 migrations. There are **no v1.16 release blockers**; v1.16 is an audit/hardening release, and the 10-audit set found only deferrable, non-blocking follow-ups.

- **Version surfaces:** all 9 are aligned at **1.15.0** and correctly wired (CLI prints `Portier CLI <v>`, replay prints `Portier replay <v>`, the Go service reports it via `app.New`, the TS server reads `package.json`). The only manual-bump risks are the **two hardcoded OpenAPI surfaces** (`OPENAPI_DOC_VERSION`, runtime schema `example`) flagged in audit #1 — now **documented** in the release checklist (RR-1 fixed).
- **OpenAPI flow:** canonical `server/build/api/openapi.json`, tracked synced copy `docs/openapi.json`; regeneration is **deterministic** (re-run produced no git diff); `validate:openapi:go` is green; `apidoc:release` copies the primary into a release dir without regenerating. No stale `docs/api/openapi.json` or `generate:apidoc` references anywhere in product docs/scripts (the maintainer's rename is fully consistent).
- **Package/runtime:** the package layout is validated (CLI+service binaries, `server.js`, `web/`+`index.html`+`assets`, **`api/openapi.json`**, `readme.txt`; absence of `node_modules`/`sources`/`rules.json`/`.env`/`client`/`server`); smoke starts the packaged Go binary on a **free port** in a temp dir, verifies `/api/health` + the web UI at `/`, and stops cleanly.
- **Release validation matrix:** the checklist's "Before A Version Release" section is comprehensive (lint/typecheck/test/build/check + validate:config/contract/openapi:go/coverage/cli/replay + build:client/test:e2e/runtime:smoke + release-artifact + platform-service validation).
- **Platform scripts:** all three platforms have build + service-validation scripts; Windows has an Inno Setup installer (`scripts/windows/release/portier.iss`) + portable zip; macOS/Linux ship portable tar.gz. **Docs are honest** — README states `.pkg`/`.deb`/`.rpm` are out of scope and installer.md frames WiX/MSI as a future product decision. Native macOS/Linux installers and the upgrade path are correctly **v1.18 work**.

**No blocking findings.** **Remediation performed:** two tiny, explicitly-permitted, no-behavior checklist additions — a **"Version Surfaces To Bump"** list (closes RR-1 + audit #1's hardcoded-OpenAPI follow-up) and adding **`api/openapi.json`** to the documented package-layout block (closes RR-2: doc/validator drift). Non-blocking notes carried into the synthesis: the whole v1.16 follow-up backlog (R-1/v1.17, O-1, S-1/L-1/v1.19, docs-completeness items), classified in §13. **Recommended next step: produce the v1.16 synthesis-and-fix-plan**, execute only MUST/SHOULD fixes, then bump versions + finalize the changelog + tag (the deliberate release step, not done here).
