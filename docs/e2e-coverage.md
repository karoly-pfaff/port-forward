# E2E Coverage

Workflow coverage baseline for Portier E2E tests (Playwright). Updated at v1.5.0 (2026-06-09).

## Setup

- **Test runner:** Playwright (Chromium, Desktop Chrome)
- **Command:** `npm run test:e2e` (requires `npm run build:client` first — or use `npm run test:e2e:fresh`)
- **Server:** TypeScript server started by Playwright webServer on port 47890
- **Config:** Isolated temp config at `test-results/portier-e2e-config.json` (generated by globalSetup)
- **State isolation:** `clearAllRules()` API helper runs before each test
- **Real vs mocked:** All tests run against a real TypeScript server. No API mocking. TCP and UDP forwarding use in-process echo servers on dynamic free ports.

## Real Runtime vs Mocked API

All current E2E tests use the **real TypeScript server** (no API mocking):

- App load, CRUD, import/export, diagnostics, API docs, settings: real server, in-memory state only.
- TCP real forwarding: in-process TCP echo server via `tests/e2e/helpers/network.ts`.
- UDP real forwarding: in-process UDP echo servers via `tests/e2e/helpers/network.ts`.
- Live Connections: real `/api/connections` endpoint; connections.spec.ts H starts a real rule.

No fixtures are injected into the server at test time beyond the empty initial config. All state is set up via API helpers (`createRule`, `startRule`, etc.) or the UI.

## E2E Gaps and v1.5 Readiness Notes

### Covered for v1.5 (complete)
- Config export / import merge / import replace with confirmation — all covered.
- Validation error display (name required) — covered.
- Settings page renders and shows config/runtime area — covered.
- Rule list state after import — covered in settings.spec.ts (replace) and portier.spec.ts (merge).
- Live Connections page and all tab/filter/toggle controls — covered (8 tests).
- API Docs lists `/api/connections` — covered.
- Plan & Apply UI: plan preview, apply, success message — covered in settings.spec.ts.

### Known gaps (non-blocking for v1.5 feature work)
- **Server offline / API error state**: no test exercises the error banner shown when the backend is unreachable. Add in a future slice.
- **Duplicate binding server error**: the friendlyErrorMessage transform is unit-tested but not exercised E2E.
- **Status filter on Live Connections**: same Clear-all mechanism already tested for protocol filter; gap is acceptable.
- **TCP/UDP connections visible in table**: requires holding a live connection open across a page navigation and refresh cycle — feasible but complex; defer to v1.5 real-traffic smoke tests once plan/apply is wired.
- **Diagnostics export bundle**: the Settings diagnostics export flow is not tested E2E; covered by unit tests in `diagnosticsExport.ts`.
- **Accessibility / keyboard nav smoke**: not yet automated; propose adding one focused test per v1.6 audit.
