# E2E Coverage

Workflow coverage baseline for Portier E2E tests (Playwright). Updated at v1.5.0 (2026-06-09).

## Setup

- **Test runner:** Playwright (Chromium, Desktop Chrome)
- **Command:** `npm run test:e2e` (requires `npm run build:client` first — or use `npm run test:e2e:fresh`)
- **Server:** TypeScript server started by Playwright webServer on port 47890
- **Config:** Isolated temp config at `test-results/portier-e2e-config.json` (generated by globalSetup)
- **State isolation:** `clearAllRules()` API helper runs before each test
- **Real vs mocked:** All tests run against a real TypeScript server. No API mocking. TCP and UDP forwarding use in-process echo servers on dynamic free ports.
- **Port allocation (Test-A note; confirmed at Fix Slice 3):** E2E runs serially (`workers: 1`, `fullyParallel: false`), so only one spec runs at a time and no two E2E tests race for a port. The `tests/e2e/helpers/port.ts` `getFreePort` helper still uses the allocate→close→return pattern; because of the serial execution this is not an intra-suite EADDRINUSE risk, only a rare cross-process one against the single dedicated server. **Fix Slice 3** finished the bounded bind-retry / live-handoff migration for the parallel TS unit suites (`udp-forwarder.test.ts` listen binds + UDP targets, `forward-manager.test.ts` manager `startRule` + TCP targets) and **deliberately left these E2E helpers as an accepted, bounded residual** for the reason above — the bounded bind-retry pattern is the recommended follow-up only if these helpers are ever made parallel. The remaining parallel-suite residual is the HTTP `/start` bind site (behind the handler) in `server/sources/api.test.ts` / `service/sources/api/api_test.go`, a larger HTTP-level follow-up. The Go service and TS server unit suites — which DO run in parallel — were hardened in Test-A and Fix Slice 3.

## Real Runtime vs Mocked API

Almost all E2E tests use the **real TypeScript server** (no API mocking):

- App load, CRUD, import/export, diagnostics, API docs, settings: real server, in-memory state only.
- TCP real forwarding: in-process TCP echo server via `tests/e2e/helpers/network.ts`.
- UDP real forwarding: in-process UDP echo servers via `tests/e2e/helpers/network.ts`.
- Live Connections: real `/api/connections` endpoint; connections.spec.ts H starts a real rule; **connections.spec.ts I (Test-E)** starts a real TCP rule, holds a forwarded client socket open, and asserts the populated table row from real `/api/connections` data.

**One deliberate exception (Test-E):** `connections.spec.ts J` uses Playwright `page.route("**/api/connections*", route => route.abort())` to force the connections API to fail at the browser layer — the only way to deterministically exercise the view's `role="alert"` error banner. Everything else (the app shell, navigation) still loads from the real server; only the connections fetch is intercepted. This is route interception, not a mocked runtime.

No fixtures are injected into the server at test time beyond the empty initial config. All state is set up via API helpers (`createRule`, `startRule`, etc.) or the UI.

## Selector policy (Test-E)

E2E selectors prefer **accessibility/user-visible** anchors over CSS classes tied to styling:

- Roles (`getByRole("table", { name: "TCP connections" })`, `getByRole("alert")`, `getByRole("tab"/"button", …)`).
- Accessible names / labels (`getByLabel(…)`, the `input[aria-label="Auto-refresh"]` attribute selector for reading a visually-hidden toggle's state).
- Visible text for user-facing controls (clicking the "Auto-refresh" label; asserting the "Listen address" diagnostic check).

Test-E removed the brittle `label.auto-refresh-toggle` and `.diag-panel-title` / `.diag-panel-body` CSS-class selectors. Exact-copy assertions are kept only for short, stable empty-state messages and contractually meaningful strings; richer assertions use roles or `{ exact: true }` text to avoid strict-mode ambiguity.

### Covered in v1.6 Test-E
- **Live Connections populated TCP table**: `connections.spec.ts I` — a real forwarded TCP connection held open during the fetch renders as a populated row (rule name, `127.0.0.1` endpoints, "Active" status); the empty state disappears and the TCP tab count goes non-zero.
- **API-failure error banner**: `connections.spec.ts J` — `page.route` aborts `/api/connections`; the view shows a `role="alert"` banner with a non-empty message and the app stays usable (tabs still render).
- **Brittle selector cleanup**: removed `label.auto-refresh-toggle` (now role/label/visible-text) and `.diag-panel-title` / `.diag-panel-body` (now the accessible "Close diagnostics" button + the user-visible "Listen address" check).

### Remaining gaps (non-blocking)
- **Duplicate binding server error**: the friendlyErrorMessage transform is unit-tested but not exercised E2E.
- **Status filter on Live Connections**: same Clear-all mechanism already tested for protocol filter; gap is acceptable.
- **UDP sessions visible in table**: the populated-TCP-table pattern proves the table path; holding a UDP session "active" across a browser fetch is harder to keep deterministic, so it is deferred (the UDP forwarding/data paths are covered by `udp.spec.ts`).
- **Diagnostics export bundle**: the Settings diagnostics export flow is not tested E2E; covered by unit tests in `diagnosticsExport.ts`.
- **Accessibility / keyboard nav smoke**: not yet automated; propose adding one focused test in a future slice.
